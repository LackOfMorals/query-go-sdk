## Finding #13 — HTTPS enforcement (by design)

HTTPS enforcement is intentionally left to the caller. The SDK is a general-purpose client that can be used against local instances, Docker containers, cloud-hosted databases, or custom deployments, each with different TLS configurations. Forcing HTTPS in the SDK would block legitimate HTTP use-cases (local development, CI, private networks with TLS termination elsewhere).

`WithBaseURL` godoc documents the responsibility explicitly:

> The SDK does not enforce HTTPS — it is the caller's responsibility to use an appropriate scheme for their deployment. Use HTTPS for any server that is not on a trusted loopback interface.

## New issue found during re-review (fixed in this pass)

### protectedHeaders keys were mixed case — protection was broken (`client.go`)

The fix for finding #4 added `"Authorization"` and `"Accept"` to `protectedHeaders`, but the lookup uses `strings.ToLower(k)`:

```go
if _, protected := protectedHeaders[strings.ToLower(k)]; !protected {
```

Mixed-case map keys (`"Authorization"`, `"Accept"`) never match after `ToLower`, so the protection was silently inoperative. Fixed in this pass — all keys are now lowercase and consistent:

```go
var protectedHeaders = map[string]struct{}{
    "authorization": {},
    "content-type":  {},
    "accept":        {},
    "user-agent":    {},
}
```

`"user-agent"` was also restored (it had been dropped from the original set).
